# 阶段 3 说明：训练模型、检验效果

截图在 `docs/screenshots/stage3/`。

## 1. 验收结果

以下数字都来自默认配置的一次真实训练：DS-v1，按运行周期划分（周期 1–3 训练、周期 4 检验、周期 5 不用），默认参数。

| 验收标准 | 结果 |
|---|---|
| XGBoost 明显优于基线 | 检验集（周期 4，130 个样本）上，统一模型 XGBoost 偏差 **4.0 ℃**，基线（沿用上一个校核值）**6.4 ℃**，**降低 37%** |
| 分工况对比在高负荷上有差异 | XGBoost 高负荷偏差：统一模型 **3.3 ℃**，分工况多模型 **17.4 ℃**。随机森林也一样（4.4 → 17.4 ℃） |
| 响应方向测试能通过 | 4 项全部符合（见第 3 节） |
| 适用范围能生成并审核 | 自动生成 10 个输入的 P1–P99 范围、支持的工况、马氏距离阈值、3 条人工规则。人工放宽了稀释蒸汽和稀释比的范围并填写依据；不填依据时审批会被拦下，提示"已调整但未填写调整依据" |
| 可以审批发布 | XGB-V1 依次经过"待检验 → 检验通过（自动）→ 已发布"，并打包到 `var/models/S1/published/XGB-V1/`（见第 2 节） |

分工况多模型在高负荷上差很多，原因是：高负荷的训练样本只有 30 条，全部来自周期 3 后期（第 50–62 天，结焦重）；而检验集里的高负荷在周期 4 早期（第 12–21 天，结焦轻）。树模型不会外推，单独建模就学不准。结论里会自动写出"分开后反而更差……建议用统一模型"。这是真实算出来的结果，没有为了凑验收去调整。

| EXP-03 | 统一 | 随机森林 | 4.2 | 4.2 | 4.4 | 14.5 | −33% | 85% |

| EXP-05 | 分工况 | 线性回归 | 3.6 | 3.3 | 4.7 | 11.8 | −44% | 78% |

这套数据里线性回归最好，因为生成数据时输入和壁温基本是线性关系。我没有为了让 XGBoost 排第一去修改数据或算法。

## 2. 实现了什么

### 训练模型（四步）

**第 1 步：训练数据**
- 数据去向漏斗，每一步都由真实数据算出：原始时段 7,296 h → 排除后 6,888 h → 质量剔除后 6,203 h → 只保留纳入工况 6,128 h → 有校核值的样本 709 条。
- 训练表预览显示真实数据的前 5 行。
- 训练表的组成：
  - 校核样本取自数据版本（DS）。
  - 输入列由共用计算链算出，使用 DS 引用的规则版本（R-vN）。
  - 工况有两套：离线工况用来挑选训练数据、做分组统计；实时工况作为模型输入，也用于分工况时选择子模型。

**第 2 步：建模方式**
- 三种方式：统一模型（工况作为独热输入）、分工况多模型（某工况训练样本少于 15 条时不单独建模，该工况不输出）、只训练主工况。
- 系统按各工况的样本占比给出推荐；可以勾选同时训练另一种方式做对比。
- 训练 / 检验划分：
  - 按运行周期：每个周期可设为训练、检验或不用；默认最后一个完整周期做检验，未结束的周期不用。
  - 按时间：最后 20% 做检验。
- 显示检验集中每种工况各有多少个样本，样本偏少时提示。

**第 3 步：算法与参数**
- 算法：基线（必跑）、线性回归（Ridge）、随机森林、XGBoost；LSTM 置灰，留到阶段 5。
- 参数方式：
  - 默认值。
  - 自动调参：Optuna TPE，20 / 40 / 80 轮；评估用训练集内按时间顺序的交叉验证（TimeSeriesSplit），**不随机抽样**。
  - 手动设置。
- 预测区间 P10–P90：
  - XGBoost 用分位数回归。由于小样本时区间偏窄，再按时间顺序交叉验证做一次共形校准（CQR）。
  - 线性回归和随机森林用按时间顺序交叉验证的样本外残差分位数。
- XGBoost 单调约束：来自模板（燃料气流量 +1），作用于燃料气的当前值、滞后值和均值列。

**第 4 步：结果对比**
- 后台线程池训练，同时最多 3 个实验；每个实验分别显示进度条和当前步骤，离开页面也会继续训练。
- 显示每个实验的总体偏差、正常稳定和高负荷下的偏差、最大偏差、比基线好多少、区间覆盖率。
- **输入重要性**：每个实验单独计算，在检验集上逐列打乱后看偏差增加多少（℃）。XGBoost 最重要的三项是：本周期运行天数 3.2、炉管压降 1.9、炉膛温度 10 分钟均值 1.0。
- **结论**按规则自动生成：最好的实验、XGBoost 与最好算法的差距、统一与分工况在高负荷上的对比。
- **追溯**：每次训练是一个"批次"，记录 DS-v / R-v / WC-v / F-v，并把工况方案和输入量配置的快照一起保存。之后再改配置，不影响已训练的模型，也不影响检验和发布。
- 历史批次可以展开查看；前面几步的配置改动后，会提示"结果基于旧配置"。

### 检验效果

候选模型送来后，系统在后台**自动完成全部计算**，大约需要 10 秒。

**1. 回放结果**
- 回放范围：检验周期（周期 4），加上训练时没用过、更新的周期（周期 5），共 173 个样本。
- 指标：候选平均偏差 4.0 ℃，基线 6.8 ℃；还有最大偏差和回放时段。
- 曲线图：
  - 每小时一个估计值，带 P10–P90 区间；
  - 叠加校核值；
  - 如有在线模型，并排画出它的曲线。
- 按工况、按周期分组统计；误差分布直方图；区间覆盖率（94.8%，偏宽，标为"注意"）。

**2. 响应方向**
- 做法：在回放数据上把某个输入的**原始序列**改变规定幅度，重新走同一条计算链（处理规则 → 工况 → 加工输入），其他输入不变。"本周期运行天数"直接加 10 天。
- 期望方向可以编辑。

**3. 适用范围**
- 自动生成，人工审核。
- 单变量范围：当前值列和组合量列，各取训练数据的 P1–P99，并配分布小图。
- 支持的工况。
- 马氏距离：标准化 + Ledoit-Wolf 收缩协方差，阈值可取 95 / 97.5 / 99 / 99.5 / 99.9 分位数。
- 人工补充规则：
  - 输入质量异常；
  - 烧焦或停炉结束、重新投料后 N 小时内；
  - 某参数 N 分钟内变化超过 X%。
- **修改时实时预览**：适用占比（回放时段按小时统计）、适用时段的偏差、不适用时段的偏差、每类原因各占多少小时。
- 调整过的范围必须填写依据；可以保存草稿，也可以从训练数据重新生成。

**4. 结论与审批**
- 结论自动生成；检验报告编号为 VR-001。
- 状态流转："开发中 → 待检验 → 检验通过 → 已发布 → 已归档"。
  - 自动检验没有"未通过"项时，自动进入"检验通过"；
  - 有任何一项未通过就不能发布；
  - 可以退回修改；
  - 发布新版本时，旧的在线版本自动归档；
  - 每次状态变化都有记录。
- **发布时打包成一个版本**：`package.json` 包含模型参数、数据版本、处理规则 R-vN 全文、工况方案 WC-vN、输入量配置 F-vN、参数清单、适用范围（已审核）、检验报告摘要、审批人和时间；同目录下另存 `model.pkl`。发布后适用范围不能再单独修改。

**场景概览**会同步显示当前在线模型、已训练的次数和最好偏差、各候选的状态。

### 测试（新增 5 个，共 40 个，全部通过）

- **基线**：严格只用预测时刻之前的校核值，同一时刻的不能用。
- **调参用的交叉验证**：每一折都是用过去的数据预测未来。
- **自动调参与区间**：调参能跑通，区间覆盖合理。
- **适用范围判定**：正常、超范围、组合异常、不在支持工况、输入缺失五种情况都判对；调整范围不填依据会被拦下。
- **完整接口流程**：训练 → XGBoost 比基线好 20% 以上 → 统一与分工况在高负荷上的差别大于 1 ℃ → 送检 → 响应方向全部符合 → 不填依据不能审批 → 填写依据后发布 → 发布后不能单独修改适用范围 → 发布包内容完整。

## 4. 示例数据的调整（需要说明）

为了让训练集里有高负荷样本，我把**第一段高负荷从 09-03～09-12 移到 07-18～07-30**（周期 3）。第二段仍是 09-03～09-12（周期 4，即检验集）；11 月那段不变，留给上线回放。

原来的两段高负荷（09 月、10 月）分别落在周期 4（检验）和周期 5（不用）里，训练集里一条高负荷样本都没有，"分工况对比"就无从谈起。仍然是"两段高负荷"，其他随机数不受影响。阶段 1、2 文档里的部分数字有小幅变化（例如高负荷时长），结论不变：规则判定与埋入事件总体一致 99.5%，燃料气时滞峰值仍为 8 分钟。

## 5. 与原型的差异

| 位置 | 原型 | 现在 | 原因 |
|---|---|---|---|
| 训练数据漏斗 | 用随机数估算 | 每一步都来自真实计算：质量剔除取自数据版本保存的质量标记，工况取自 WC 快照 | SPEC 第 4.5 节 |
| 结果表 | — | 增加"区间覆盖"列 | 区间是否可信，在训练阶段就能看到 |
| 输入重要性 | 0–1 的相对值 | 打乱后偏差增加多少（℃） | 单位有意义，每个实验单独计算 |
| 检验效果的对比对象 | 写死"在线 XGB-V3" | 有在线模型时与它并排比较；没有时与基线比较 | Demo 从空白开始，没有预置在线模型 |
| 回放曲线 | 示意曲线 | 每小时一个估计值，加区间和校核值；输入无效或工况不支持的地方曲线空缺，表示不输出 | — |
| 适用范围的变量 | 7 个关键变量 | 模型里每个参数的"当前值"列，加上组合量，共 10 个 | 滞后值、均值等派生列与当前值同源，不必重复检查 |
| 多变量检查方法 | 马氏距离 / 孤立森林 | 只实现了马氏距离；孤立森林选项置灰 | 范围控制 |
| 适用范围预览 | 用随机数估算 | 在回放数据上真实计算，并按原因统计不适用的小时数 | SPEC 第 4.6 节 |
| 训练批次 | 只记录数据版本 | 同时记录 R / WC / F 版本，并保存快照 | 一切可追溯，改配置不影响已训练的模型 |
| LSTM | 可选 | 置灰，标"阶段 5（可选）" | SPEC 第 6 节 |

## 6. 已知问题

- **适用占比偏低（约 61%）**：这是真实的数据漂移，自动范围严格按训练数据 P1–P99 生成。
  - 周期 4–5 中，稀释蒸汽、横跨段温度、稀释比有 4–13% 的时间超出训练范围；马氏距离判为组合异常的约 14%。
  - 另外，烧焦、开炉期间输入无效或工况不支持，约占回放时段的 10%。
  - 审核时可以放宽范围并填写依据，界面也会给出这样的提示。阶段 4 在线运行时，不适用的时段同样不输出。
- **回放最大偏差 57.7 ℃**：出现在 10-14 01:00，也就是烧焦刚结束、刚开始投料时。这个样本"本周期运行天数"为 0.04，低于适用范围下限，上线时会判为不适用、不输出。
- **XGBoost 的 P10–P90 区间偏宽**（覆盖 94%，目标 80%），检验结果标为"注意"，不影响发布。原因是共形校准用的交叉验证每折训练数据比全量少，估出来的放宽量偏保守。
- **分工况多模型**：某个工况训练样本少于 15 条时，不单独建模，该工况不输出。
- **单调约束**：只来自模板，目前只有"燃料气流量"一项，界面上不能编辑。
- **训练表缓存**：同一配置重复训练时会复用已算好的输入列；第一次计算约 0.5 秒。

## 7. 怎么验证

1. 启动服务（每次启动都会自动重新构建前端）。Windows 下运行：

   ```bat
   scripts\start.bat
   ```

   Linux / macOS 下运行：

   ```bash
   ./scripts/start.sh
   ```

2. **选数据**：点"生成训练数据"，得到 DS-v1。如果之前已经生成过，可以跳过这一步。
3. **训练模型**：保持默认设置，点"开始训练"，约 20 秒后 7 个实验全部完成。在结果表中点选"统一模型 · XGBoost"，查看输入重要性和结论，然后点"送去检验效果"。
4. **检验效果**：等待约 10 秒，自动检验完成。
   1. 在"适用范围"里把稀释蒸汽流量的上限改为 17.8。
   2. 先不填依据，直接点"审批通过并发布"，会提示需要填写依据。
   3. 填写依据后再点一次，状态变为"已发布"。
5. **场景概览**：会显示当前在线模型 XGB-V1。

后端测试（Windows）：

```bat
cd backend
.venv\Scripts\python -m pytest -q tests
```

后端测试（Linux / macOS）：

```bash
cd backend && .venv/bin/python -m pytest -q tests
```
