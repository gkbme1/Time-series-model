## 1. 实现了什么

### 示例数据（`scripts/gen_demo_data.py`，约 5 秒，固定种子）

- **时间范围**：2026-01-01 至 2026-11-30，1 分钟一个点。按约定，11 月留给上线回放。
- **设备**：1 号炉 BA-101 和 4 号炉 BA-104。BA-104 位号为 FI-4021 等，参数名与 1 号炉相同，增益、偏置、结焦速率和事件时间都不同。
- **参数**：22 个，包含原型设备树里的全部参数，另外补了烧焦空气阀开度 HV-1015。
- **埋入的事件（BA-101）**：

  | 事件 | 时间 |
  |---|---|
  | 停炉检修 | 03-08～03-21 |
  | 烧焦 | 05-28～05-30、08-20～08-22、10-12～10-14 |
  | 升温开炉 | 每次烧焦、检修结束后 12 h |
  | 高负荷 | 09-03～09-12、10-20～10-26 |
  | 原料变重 | 06-25～07-12、09-18～10-05 |
  | 燃料气总管压力扰动 | 09-25 03:00～06:00 |
  | DCS 中断 | 06-14～06-16 |
  | 第一个周期起点 | 2025-12-13，早于数据起点 |

  11 月另埋了几件事，留给阶段 4 产生"不适用"的情形：高负荷、原料切换、炉膛温度偏高、高负荷下稀释比偏低。全部事件记录在 `data/_truth/events.json`。
- **物理关系**：
  - 壁温由燃料气（5 min 纯滞后 + 6 min 时间常数）、原料（7 + 9）、稀释蒸汽、结焦（随本周期运行天数加速上升，周期末高 25–35 ℃）和原料密度共同决定；原料增加、燃料气不变时，壁温下降。
  - 燃料气 = 按原料的前馈 + 独立的操作调整，所以响应方向是学得出来的。
- **数据质量问题**：每个参数注入冻结段、尖峰、超量程和缺失段（包括长缺失），每一处都记录在 `data/_truth/*_quality_log.csv`。
- **校核数据**：
  - 1# 管热电偶：周期后段先漂移再断偶，烧焦后更换。有效率 73.5%。
  - 红外测温：每班一次，测 1#–8# 管。每个读数带管位偏差、仪器偏差、测量人偏差和随机误差，偶有漏班和录入错误。
  - 检修测温：停炉期间的记录，默认不用于训练。
- **数据自检**（详细数字由生成器自检得出，不在界面上）：
  - 在"正常稳定"工况下，燃料气对 1# 管热电偶的互相关（先减去 60 min 滑动均值）峰值在 **8 分钟**，r = 0.65。阶段 2 的时滞分析会在界面上真实计算这个值。
  - 用前 3 个周期训练、周期 4 检验，做了一次快速试算：基线偏差 6.2 ℃，线性回归 2.7 ℃，XGBoost 3.5 ℃。说明这套数据能支撑阶段 3 "XGBoost 明显优于基线"的验收。阶段 3 会做正式训练和调参。

### 后端（FastAPI + SQLite + Parquet）

- **数据源接口**：`core/datasource.py`，提供 `DataSource` 抽象类和 `FileDataSource` 实现，以后接 XBase 时替换实现即可。
- **处理规则**：`core/quality.py`。
  - 规则共六类：物理范围、冻结检测、尖峰处理、缺失补齐、平滑（可选）、烧焦期间，每条都有"触发后"的处理方式。
  - **原始数据不改**。规则只产生逐分钟的质量标记（位掩码）和处理后的值，两者都另存。
  - **所有判定只往回看**：
    - 冻结：过去 N 分钟全部有值，且最大值减最小值不超过阈值。
    - 尖峰：与过去 5 分钟中位数比较。
    - 补齐：只用上一个有效值，缺失超过上限的部分不可用。
  - 默认阈值：物理范围取参数表量程（标"来自本体"）；尖峰阈值取历史上"偏离过去 5 分钟中位数"的 99.9% 分位数再乘 1.5；模板中的工艺经验值优先。用注入日志核对过，主要参数的尖峰全部检出，正常运行期间的误报约 0.007%。
- **工况规则引擎**：`core/regime.py`。阶段 1 只用模板默认规则，标出烧焦期间并统计校核点覆盖了哪些工况。规则引擎有 offline 和 causal 两种模式，都已实现。
- **校核样本**：`core/calib.py`。按测量时刻配对，不插值。"按时刻平均"时，同一次巡检至少测到 4 根出口段管才算一个样本。热电偶取整点值，失效判定只看历史。
- **数据版本 DS-vN**：保存配置快照、处理后的值、质量标记和校核样本到 `var/datasets/S<场景>/DS-vN/`。规则有改动时会先自动保存为新的 R-vN，版本之间相互引用。
- **单元测试**：19 个，全部通过。其中"不用未来数据"测试会把某时刻之后的数据改成噪声、缺失、尖峰或冻结，再检查该时刻及以前的质量标记和处理值完全不变；还测了截断后计算与全段计算一致，以及 causal 工况判定不受未来数据影响。

### 前端（React + TypeScript + Vite + ECharts）

页面结构、文案和样式移植自原型。本阶段可用的页面：

- 首页
- 新建项目、打开项目、关闭项目
- 项目树
- 项目概览
- 场景概览：流程卡片里"选数据"一栏是真实信息
- 新建场景向导：可以在 BA-104 上新建场景
- 场景模板库
- **选数据全部功能**：
  - 估算目标
  - 设备树参数选择：搜索、只看推荐、整组勾选
  - 时间范围（含快捷按钮）和排除时段
  - 多参数预览：最多 5 个参数共享时间轴，可叠加校核值，可标出处理过的时段；滚轮缩放或拖动后由后端重新降采样
  - 数据质量诊断
  - 按参数编辑处理规则，改动后诊断和影响比例立即重算
  - 影响汇总：给出影响最大的参数，以及去掉哪个参数能多保留多少样本
  - 训练用校核数据：各来源的可用点数、按工况覆盖，支持 CSV / Excel 导入，导入后先待审核
  - 生成数据版本

## 2. 当前示例场景的真实计算结果（默认配置）

- **参数**：8 个推荐参数，时间范围 2026-01-01 至 10-31，排除停炉检修和 DCS 中断，有效 287 天。
- **质量诊断**：
  - 烟气氧含量完整率 95.6%、冻结 15 段，评级 B；其余参数评级 A。
  - 出口温度有 4 段超量程读数 999。
- **影响**：约 9.9% 的时间点因为至少一个参数无效，不能参与训练。影响最大的是烟气氧含量（5.3%），去掉它能多保留约 4.8% 的时间点。
- **校核样本**：红外测温按时刻平均得到 786 个样本，其中正常稳定 743 个、高负荷 41 个。热电偶整点值 5,322 个，只作参考。

## 3. 与原型的差异

| 位置 | 原型 | 现在 | 原因 |
|---|---|---|---|
| 处理规则文案 | "≤2 min 线性插值（仅用历史值）"；"单点跳变 > X 且 1 min 内恢复 → 剔除" | "≤2 min 用上一个有效值补齐（仅用历史值）"；"偏离过去 5 min 中位数 > X → 剔除（只看历史）" | 已确认的第 3 点：原文需要未来数据 |
| 处理规则 | 只能开关、选处理方式 | 还可以直接改阈值（上下限、窗口、阈值） | SPEC 要求"按参数配置处理规则"；手工改过的物理范围标"手工修改" |
| 数据质量表 | 完整率、冻结段、跳变、超范围、评级 | 多一列"可用率"；评级按可用率（≥98% A，≥93% B） | 完整率只反映缺失，可用率才反映按规则实际能用多少 |
| 数据预览 | 日均值曲线 | 每个点是一个时间桶的均值，加最小–最大阴影带；缩放后重新取数，最细到分钟 | SPEC 要求"数据量大时由后端降采样" |
| 训练用校核数据 | 热电偶整点值算作校核点 | "按时刻平均"时热电偶标"仅作参考"，不计入训练样本 | 已确认的第 2 点 |
| 导入校核数据 | 刚导入、待审核 | 在来源行上点"审核通过 / 作废"（整个文件一起审） | 逐条审核放在阶段 4 的"在线校核"页 |
| 生成训练数据表 | 校核点 | 校核样本 | 按时刻平均后，一个样本对应一次巡检 |
| 场景概览 4 个指标 | 有数值 | 显示"—"，并注明上线后计算 | 阶段 4 用真实计算填充 |
| 项目概览 | 6 个在线实例、XBase 已连接 | 0 个实例、数据源"本地文件" | 已确认的第 4 点 |
| 新建场景向导 | 1–6 号炉；有"可信等级""输出"选项 | 只列有数据文件的 BA-101、BA-104；目标的细节统一在"估算目标"里设置 | 避免两处设置同一件事 |
| 模板库 | 6 个模板 | 6 个都在，只有"裂解炉 · 炉管壁温"内容完整，其余标"Demo 仅内容示意"；"另存为模板 / 导入模板"按钮置灰 | 已确认的第 4 点 |
| 数据文件 | — | `tags.csv` 增加 `furnace` 列；校核 CSV 增加 `entered_at` 列；增加 `calib/_sources.json` 来源清单 | 已确认的第 6 点 |
| 示例事件 | — | "两次原料切换"按两段重原料时期实现（06-25～07-12、09-18～10-05，即 4 次切换） | 如果重原料只出现在检验周期，模型没见过它，检验时会有约 5 ℃ 的系统偏差 |

## 4. 已知问题

- **冻结检测要满一个窗口才能判定**：冻结开始后的前 30 分钟不会被标为冻结。这是"只用历史数据"带来的必然结果，训练和上线的行为是一致的。
- **真实的大幅阶跃可能被误标为尖峰**：尖峰只看历史，阶跃后最初 2–3 分钟可能被当作尖峰。默认阈值已经按历史分位数放宽；烧焦、停炉开始和结束的瞬间也会产生少量跳变和超范围标记，不过这些时段本来就不参与训练。
- **默认阈值用整个数据文件估计**（包括 11 月）：这只用来给出建议的默认值，不参与训练；用户可以修改。
- **首次计算稍慢**：规则改动后，第一次重算选数据页约需 1–2 秒，之后走缓存约 0.3 秒。
- **日期输入框的显示格式跟随浏览器语言**：英文环境下显示为 mm/dd/yyyy。
- **不支持删除项目或场景**：原型里也没有这个功能。
- **前端打包体积较大**（主要是 ECharts），构建时有提示，不影响使用。

## 5. 怎么验证

```bash
./scripts/start.sh
```

浏览器打开 <http://127.0.0.1:8000>，进入 `1号炉 炉管壁温软测量 → 选数据`：

1. 在"数据处理规则"里选"烟气氧含量"，把"冻结检测"的触发后处理改成"仅标记，照常使用"。左侧的影响比例会立即下降，从 9.9% 降到 9.0%。
2. 在预览里勾选"炉膛温度"，用滚轮放大到某一周，可以看到红色的冻结段和橙色的尖峰点。
3. 点"生成训练数据"，得到 DS-v1，表中显示它对应的规则版本。

后端测试：

```bash
cd backend && .venv/bin/python -m pytest -q tests
```
