# 阶段 2 说明：分工况（含运行周期）、加工输入

截图在 `docs/screenshots/stage2/`。

## 1. 验收结果

| 验收标准 | 结果 |
|---|---|
| 规则判定结果与生成数据里埋入的事件基本吻合 | 按模板默认规则逐分钟判定，2026-01 至 10 月与真实工况的**总体一致率 99.5%**（见下表）。 |
| 时滞分析在燃料气上找到约 8 分钟的峰值 | 燃料气 → 1# 管热电偶的峰值在 **8 分钟**，相关系数 0.70，约 31.5 万个时间点，只用"正常稳定、高负荷"两个工况。 |
| 不用未来数据的单元测试通过 | 通过。后端测试共 35 个，全部通过。 |

**规则判定与真实工况的一致率**

| 工况 | 离线判定 | 实时判定 |
|---|---|---|
| 正常稳定 | 100% | 100% |
| 高负荷 | 99% | 98% |
| 烧焦 | 100% | 93% |
| 停炉 | 99% | 96% |
| 升温 / 开炉 | 82% | 74% |
| 原料切换 | 58% | 39% |
| **总体** | **99.5%** | **99.1%** |

- 离线判定用于挑选训练数据；实时判定在上线时使用，也是模型的输入。
- 实时判定要等条件持续满最短时间才认定，所以每段工况的开头会少几个小时。
- "原料切换"偏低，是因为默认规则"原料密度 6 小时内变化超过 5"要到切换进行到一半才满足。这正是"自动发现 + 人工确认"要补的部分：在界面上"自动发现"能找到全部 4 次切换，确认后即可生效。

**时滞分析的其他参考结果**

| 参数 → 对象 | 峰值 | 相关系数 | 说明 |
|---|---|---|---|
| 燃料气 → 出口温度 | 2 分钟 | 0.79 | 与生成数据设定的 1 分钟纯滞后 + 3 分钟时间常数一致 |
| 炉膛温度 → 1# 管热电偶 | 5 分钟 | 0.59 | — |
| 原料流量 → 1# 管热电偶 | — | 0.07 | 峰值不明显，界面会提示"参考价值有限"。原料只有少数几次台阶变化，去掉慢变化后几乎没有可用的变化，这种参数适合用外部参考（APC 参数给出等效 12 分钟）或手工填写 |

## 2. 实现了什么

### 分工况

- **规则引擎**
  - 条件支持：大于、小于、介于、N 小时内上升超过、N 小时内下降超过。
  - 每组规则可选"全部满足"或"任一满足"，并设最短持续时间。
  - 从上到下按优先级判定，都不满足的算"正常稳定"。规则可以上移、删除、新增。
  - 同一份代码有两种模式：
    - 离线判定：持续时间不够的整段丢掉。
    - 实时判定：持续满最短时间之后才认定，不需要未来数据。
- **模板默认规则**：停炉、烧焦、升温开炉、原料切换、高负荷。
  - 相比原型，"升温开炉"改为"原料流量介于 3–35 t/h"。原型的"出口温度 4 小时内上升 10 ℃"只能抓到开炉前几个小时，检出率 39%。
  - 新增一条"原料切换"规则。原型里点"新增工况规则"时默认生成的就是这条。
- **工况判定图**
  - 多参数共用时间轴，背景按工况着色。
  - 滚轮缩放、拖动平移，缩放后由后端重新降采样。
  - 工具按钮：＋、－、全部、适配选中、◀、▶。
  - 下方总览条可以点击跳转。
  - 显示哪些参数可以切换，也可以添加任意参数。
- **手动框选**：切到"框选标注"后拖动选择时段，可以选择已有工况，也可以新建工况。框选结果保存为手动标注，记录标注人（固定为"赵工"），可以删除。
- **自动发现**
  - 对选定的关键参数取小时均值，计算 3 小时变化量，再除以该参数小时均值的稳健标准差。超过阈值的点合并成时段，阈值：高 3.3、中 4.5、低 6。
  - 每个时段都给出"发生了什么"的描述（例如"原料密度上升约 10.9 kg/m³"），以及规则对这段时间的当前判定。
  - 人工确认（可以新建工况）或忽略后才生效，都可以撤销。和手动标注重叠的时段标为"已有手动标注"。
  - 用默认的四个参数、"中"灵敏度，找到 15 个时段：3 次开炉、3 次烧焦开始、3 次烧焦结束后升负荷、4 次原料切换、高负荷开始 / 结束，以及 09-25 的燃料气扰动。
- **最终工况的优先级**：手动 > 已确认的自动发现 > 规则。工况汇总里按来源分别列出时长。
- **工况汇总**：每种工况的时长、占比、判定来源，以及是否纳入训练。
- **运行周期**
  - 边界事件可选"烧焦或停炉"、"仅烧焦"、"不划分"。
  - 事件取持续 6 小时以上的烧焦或停炉段；相隔不到 1 天的两次事件合并为一次。
  - 第一个周期的起点可以填在数据起点之前。Demo 场景预置为 2025-12-13，按运行记录推算。
  - 默认设置下得到 4 个完整周期和 1 个未结束的周期，与原型的叙述一致。
- **工况方案 WC-vN**：规则、手动标注、确认的自动发现、纳入哪些工况、周期设置一起保存为一个版本。阶段 3 训练时引用这个版本。

### 加工输入

- **参数加工方式**：每个参数可选当前值、N 分钟前的值、N 分钟均值（窗口内有效点不少于 80% 才计算）、N 分钟标准差、N 分钟变化率（按每小时计）。所有窗口都只往回算。
- **时滞分析**
  - 对目标计算：用 1# 管热电偶，先经过失效判定。
  - 对代理变量计算：可选 1# 管热电偶、出口温度、炉膛温度。
  - 两种计算方式相同：只用纳入的工况和所选时段；双方各自减去 60 分钟滑动均值，计算滞后 0–30 分钟的互相关。
  - 导入外部数据：读取 `data/lag_refs/` 里的文件，也支持在界面导入 JSON。展示纯滞后、时间常数和等效滞后（纯滞后 + 时间常数的一半），并画出阶跃响应曲线。
  - 手工填写：滞后、依据、说明。
  - 采用时**记录来源**，例如"对目标计算 / APC 模型参数 / 手工填写 · 操作经验"，以及具体依据；加工方式里的滞后会同步更新。
  - 相关性弱时提示"峰值不明显"；超过 25 分钟时提示请工艺人员确认。
- **组合量**
  - **公式**
    - 用 `ast` 白名单解析，不用 `eval`。
    - 支持：加减乘除、括号、数字、abs / log / sqrt、{参数名}。参数限于"选数据"里已选的参数。
    - 除数为零时，可以选"标为无效"或"沿用上一个有效值"（只用历史值）。
  - **内置算子**
    - 自事件起的累计时间（天）。
    - 自事件起的累计量（参数 × 小时）。
    - 距上次事件多久（小时）。
    - 指数平滑（时间常数，单位天）。
    - 事件可选"烧焦或停炉结束"或"原料切换"，由工况规则**实时判定**，上线时也是这样。
  - **脚本**：只有界面，可以编辑和保存，状态显示"待审核"。"试算"会提示"Demo 版本不执行脚本"。脚本不执行任何代码，也不进入训练表。
  - **试算预览**：每种方式都可以试算，在所选时段内画出全时段曲线，叠加烧焦、停炉、原料切换的标记，并给出无效点数和有效比例。保存前必须先试算。
- **加工结果**：列出训练表里的每一列及其计算方式，当前共 18 列。
- **配置说明弹窗**：内容同原型，"按示例填入"可以一键填入示例配置。
- **输入量配置 F-vN**：加工方式、采用的滞后及来源、组合量一起保存为一个版本。
- **训练和上线共用同一条计算链**（`core/pipeline.py`）：处理规则 → 实时工况判定 → 加工输入。
  - 训练时对整段历史调用 `build()`。
  - 上线时（阶段 4）对"当前时刻往前一段历史"调用同一个 `build()`。

### 测试（新增 15 个，共 35 个）

- **不用未来数据**：在 05-01 至 08-31 的数据上，把某时刻之后的所有原始数据随机放大或缩小，并挖掉一段缺失。该时刻及以前的全部输入列和工况标签都保持不变。只给到该时刻为止的数据（上线时的情形）计算出的最后一行，也与全段计算结果一致。测了 3 个时刻：烧焦开始、原料切换、普通运行，覆盖 6 种加工方式和 7 个组合量。
- **这个测试在开发中抓到过一个真实问题**："除数接近零"原本用整段数据的中位数来判断，相当于用到了未来数据。已改为只看当前点（|除数| < 1e-6）。
- **公式安全**：`__import__`、属性访问、`**`、lambda、列表、条件表达式、未列入白名单的函数、`eval` 全部会被拒绝。
- **除数为零**和**内置算子**各有专门测试。
- **规则与真实工况一致**：总体一致率要求大于 98%；烧焦、高负荷、停炉各自要求大于 95%。
- **页面接口流程**：
  - 周期：5 个，第 1 个早于数据起点。
  - 时滞：峰值在 6–10 分钟之间。
  - 自动发现找到 4 次原料切换，确认后生效；手动标注能新建工况。
  - 不安全的公式会被拒绝；"本周期运行天数"试算结果正确；脚本不执行。
  - 采用滞后后加工方式同步更新；可以保存 WC-v1 和 F-v1。

## 3. 与原型的差异

| 位置 | 原型 | 现在 | 原因 |
|---|---|---|---|
| 分工况图的时间范围 | 08-01 至 10-31，逐小时 | "选数据"的完整范围，逐分钟判定；按可视范围降采样，最细到分钟 | SPEC 第 4.3 节 |
| 页面顶部 | — | 增加"工况方案 WC-vN / 输入量配置 F-vN"保存栏 | SPEC 第 5 节"一切可追溯"；原型没有版本入口 |
| 参数切换按钮 | 固定 5 个 | 显示规则用到的参数，另可加入任意参数 | 判定用的参数不一定是模型输入 |
| "升温 / 开炉"默认规则 | 出口温度 4 h 内上升 10 ℃ 且原料 < 37 | 原料流量介于 3–35 t/h | 原写法检出率只有 39%，新写法为 82% |
| 运行周期 | 第一个周期起点写死 | 可以填写"数据起点之前最近一次烧焦结束" | 数据里看不出数据起点之前的事件 |
| 自动发现的灵敏度 | 用 3 小时变化量本身的稳健标准差归一化 | 用小时均值水平的稳健标准差归一化 | 原写法在分钟级数据上过于敏感，"中"档会找出 75 段，大多是 1–2 t/h 的正常调整 |
| 算子"指数平滑" | 也要选事件 | 不需要事件 | 平滑与事件无关 |
| 时滞分析的代理变量 | 3 个 | 1# 管热电偶、出口温度、炉膛温度 | 一致 |
| 外部参考的导入 | 支持任意文件 | 只支持约定格式的 JSON | SPEC 第 1.2 节 |
| 加工方式表 | 来源提示 | 同原型；另外显示外部参考给出的建议值 | — |

## 4. 已知问题

- **实时判定的延迟**：要等工况持续满最短时间才认定，所以每段工况的开头几小时仍算作原工况。离线挑选训练数据时没有这个延迟。
- **10-12 那次烧焦被判晚了约 5.5 小时**：烧焦空气阀开度的数据在烧焦开始时恰好有一段缺失（生成数据时随机注入的数据质量问题），规则判定从 13:30 才开始。这是真实可能发生的情况，可以用手动框选补正。
- **自动发现描述里的数值**：按小时均值的最大值减最小值计算，与分钟级的峰谷差相比会偏小。
- **公式里的参数**：只能引用"选数据"里已选的参数，这一点与原型一致。
- **原料流量的互相关峰值不明显**：原因见上面第 1 节"时滞分析的其他参考结果"。

## 5. 怎么验证

Windows 下运行（或直接双击该文件）：

```bat
scripts\start.bat
```

Linux / macOS 下运行：

```bash
./scripts/start.sh
```

浏览器打开 <http://127.0.0.1:8000>，进入 `1号炉 炉管壁温软测量`：

1. **分工况 → 自动发现**：点"开始发现"，找到 15 个时段；点 `2026-09-25` 那一行，上图会跳过去，能看到燃料气扰动。"确认为"选"新建工况…"，填写名称后确认，工况汇总里会出现这种工况，来源为"自动发现"。
2. **分工况 → 框选标注**：在图上拖动选择一段时间，指定工况。
3. **加工输入 → 确定滞后时间**：默认就是燃料气"对目标计算"，柱状图峰值在 8 分钟。点"采用为该参数的滞后"，加工方式表里的来源会变为"对目标计算"。
4. **加工输入 → 组合量**：编辑"本周期运行天数"，点试算预览，曲线在每次烧焦或停炉后归零。

后端测试（Windows）：

```bat
cd backend
.venv\Scripts\python -m pytest -q tests
```

后端测试（Linux / macOS）：

```bash
cd backend && .venv/bin/python -m pytest -q tests
```
